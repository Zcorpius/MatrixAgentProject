## 2026-09-28 持续实施说明

- 默认交互请求仍为 8 轮 / 8 次工具 / 60 秒。`source_research` v1 由 Host 选择 RESEARCH：父级活动时间 30 分钟、40 次逻辑模型调用、40 次工具调用，单步最多 3 分钟。上下文仍有 8k / 32k / 64 条边界。研究窗口默认 40 分钟，包含排队；小于 30 分钟的创建参数明确拒绝。
- 固定图为三个站点检索、三个来源分析、交叉摘要与交付。Wikipedia 仅搜索片段；Crossref 为书目/已存摘要；arXiv 为作者摘要。没有正文读取，也没有动态计划。摘要至少需要两个站点，并校验模型引用属于实际提供的来源，链接由 Host 拼接。引用检查不能证明第三方断言本身真实。
- 搜索只请求固定 HTTPS API，禁止重定向、任意 URL 与凭据透传，响应最多 512 KiB；arXiv 请求预留至少 3 秒间隔。工具有 20 秒上限，HTTP 单次最多 18 秒。
- 只读检查点绑定 run/step、epoch、输入摘要、版本、数据摘要和有效期；最长 1 小时且不超过 run 到期时间。损坏/过期检查点使依赖分析失效，持久化的尝试数、调用数和活动时间不重置。无法确定是否完成的交付不盲重放。
- `ReadTransactionCompactor` 已实现旧 `web.search` 完整已核验事务的 Host 回执压缩规则，但当前发布图中的研究步骤由固定 `SourceResearchClient` 取证，AGENT 步骤未开放该工具，因此这段压缩规则尚不可达、也不计入真机验收。研究任务目前依靠分步检查点与有界来源摘要控制上下文。未来如接通只读工具路径，正文省略后仍须重新取证；未知结果、拒绝、写操作和不完整调用事务必须完整保留。
- Android 最低版本兼容性由 Lint 检查；已修正 `StringBuilder.isEmpty`、`InputStream.readAllBytes` 和 `Stream.toList` 的生产路径兼容问题。原生 UTF-8/UTF-16 和跨片段结束标记新增独立 C++ 测试。

真机探针仅在 debug 构建，通过 DUMP 权限 receiver 转给非导出的前台 service。Room 测试使用独立合成库；研究探针会创建标题明确的合成一次性计划，并经生产调度/通知链路运行。报告逐项标记质量结果；测试执行完毕不等于回答全部正确。

外部协议依据：[MediaWiki 搜索 API](https://www.mediawiki.org/wiki/API:Search)、[Crossref REST API](https://www.crossref.org/documentation/retrieve-metadata/rest-api/)、[arXiv API](https://info.arxiv.org/help/api/user-manual.html)。
