# 控制 QQ 音乐

1. 由模型理解完整用户语义，区分搜索指定内容和控制当前队列。不要机械地按“的”分割歌手和歌名；歌名、歌手名本身都可能含“的”、空格或外文。明确指定哔哩哔哩的请求必须走哔哩哔哩工具。
2. 指定歌曲时直接调用 media.qqmusic.search_songs，无须先 get_state 或 open_app。query 是搜索关键词；artist、title 分别填写用户指定的歌手和完整歌名，未指定时省略或填空字符串，保留歌名内的“的”和 Live 等版本信息。只点名歌手时不编造歌名；信息不足时澄清。工具内部负责打开搜索页面。
3. 工具返回的候选才是事实来源。media.confirmable_index 表示结构化条件唯一精确匹配：说明真实编号、歌名和歌手/专辑，询问“是否播放这首？”，停止本轮。没有该字段则列出候选，请用户指定歌名或编号；不能自行选第一首或把相似结果当作精确匹配。
4. 用户下一轮肯定答复只允许播放已明确提议的唯一候选，调用 media.qqmusic.play_search_result，index 等于 media.confirmable_index。多项待选时必须明确歌名或编号；否定答复不播放。搜索与播放不能在同一轮完成。
5. 用户明确控制当前队列时，先 get_state 确认唯一活动会话及支持动作，再调用 play、pause、next、previous 或 seek。写 Tool 包含回读；play 只恢复已有队列，不能替代指定内容搜索。next/previous 不自动重发。
6. 搜索上下文过期、界面或候选变化、辅助功能未启用时说明原因并停止，不猜测或改播当前队列。VERIFICATION_FAILED 表示未能证明目标状态；EXECUTION_UNKNOWN 表示命令可能稍后生效，不能自动重试。
